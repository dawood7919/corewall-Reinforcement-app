# معمارية الملاحظات الميدانية الجديدة

## نتيجة الجرد

يعتمد النظام السابق على `NoteEntity.body` كنص Markdown موحّد وعلى واجهات تحرير وعرض منفصلة تتعامل مع الصور والملفات عبر رموز نصية. تُحافظ عملية الاستبدال على البنية المفيدة التالية فقط: قاعدة Room ومفتاح الملاحظة، روابط الوسوم، جدولة التذكيرات، التخزين الخاص بالتطبيق، عارض الصور، وأدوات تصنيف القلم الموجودة في `stylus/StylusInput.kt`. تُستبدل شاشة القائمة، البطاقات، المحرر، التحويل النصي، أداة الرسم، والتقاط الصوت بواجهات ووثائق موحدة جديدة.

| المجال | القرار |
|---|---|
| التخزين | إضافة `documentJson` إلى `NoteEntity` لتخزين وثيقة منظمة متعددة الكتل. يظل `body` ملخصاً نصياً مفهرساً للتوافق مع السياق الهندسي والبحث القديم، وليس مصدراً لتحرير الوثيقة. |
| الترحيل | أي ملاحظة قديمة بلا `documentJson` تتحول محلياً عند فتحها إلى نص أو قائمة أو صور أو ملفات صوتية، ثم تحفظ كوثيقة جديدة. لا تفقد بياناتها أو مسارات مرفقاتها. |
| الكتل | نص، عنوان، قائمة تحقق، صورة، رسم، صوت، اقتباس، فاصل، ورابط. لكل كتلة معرّف وترتيب مستقلان حتى يمكن إعادة ترتيبها وتحريرها دون معالجة HTML أو Markdown شامل. |
| القائمة | بطاقات متجاوبة تعرض معاينة صورة/رسم، حالة قوائم، صوت، وسوم وتذكيرات، مع بحث محلي وترتيب وتحديد متعدد. |
| المحرر | محرر وثيقة بكتل قابلة للإضافة والحذف وإعادة الترتيب، وشريط إجراء سفلي لا يحجب مؤشر الكتابة مع IME، وطبقة تنسيق سياقية للنص. |
| الرسم | مساحة رسم مستقلة تستعمل تصنيف قلم S Pen وضغطه؛ وضع «S Pen فقط» يمنع الإصبع من إنتاج حبر ويبقيه للتنقل. |
| الوسائط | الصور والرسوم والصوت ملفات في تخزين التطبيق الخاص ويشار إليها من كتل منظمة. تُستخرج المسارات عند الحفظ لتستمر سياسة تنظيف الملفات الحالية. |

## المبادئ التشغيلية

كل العمليات محلية أولاً، والحفظ تلقائي ومؤجل. لا تحتاج الملاحظات إلى اتصال إنترنت. تظل التذكيرات والوسوم والأرشفة والمهملات والتثبيت ضمن `NotesStore` بعد إعادة صياغة عملياتها لتقرأ نموذج الوثيقة. تُحدَّث البطاقات والبحث من ملخص الوثيقة المحسوب، وتُحمّل الصور المصغرة بكسل وبشكل كسول.
